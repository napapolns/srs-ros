1. แหล่งข้อมูลที่ใช้

ข้อมูลในแดชบอร์ดภาพรวมสมาชิกดึงมาจาก 4 แหล่งหลัก ดังนี้:

📋
ข้อมูลสมัครสมาชิก (Input)
ข้อมูลที่กรอกตอนสมัคร — ไม่ต้องคำนวณ

ใช้สำหรับ: Field 1-18, 20, 22, 26-28

🧾
รายงานบิล (bills)
ข้อมูลระดับบิล — 1 แถว = 1 บิล

ใช้สำหรับ: Field 29, 32-35, 40-55, 58-66

🍽️
รายงานรายละเอียดบิล (bill_items)
ข้อมูลระดับเมนู — 1 แถว = 1 รายการสินค้าในบิล

ใช้สำหรับ: Field 36-39, 51, 56

🧮
คำนวณแยก (สูตรเฉพาะ)
RFM, Lifecycle, Rank — มีสูตรคำนวณเฉพาะ

ใช้สำหรับ: Field 19, 21, 23-25, 30-31

2. เงื่อนไขสำคัญในการดึงข้อมูล

⚠️
เงื่อนไขบังคับ: ทุก Field ที่คำนวณจากรายงานบิล ต้องใช้เฉพาะบิลที่มีสถานะ bill_status = "สำเร็จ" เท่านั้น (ไม่นับ "คืนเงิน" หรือ "ยกเลิก")
🚫
บิล "ไม่คิดรายได้": บิลที่ถูก flag เป็น "ไม่คิดรายได้" จะไม่ถูกนำมาคำนวณใดๆ ทั้งสิ้น ไม่ว่าจะเป็นยอดขาย ความถี่ หรือคะแนน
🌐
ทุกสาขา: Fields ที่ระบุ "ทุกสาขา" จะคำนวณรวมข้อมูลจากทุกสาขา ไม่จำกัดเฉพาะสาขาใดสาขาหนึ่ง
🔗
ความสัมพันธ์ข้อมูล: รายงานบิล (1) → รายงานรายละเอียดบิล (N) เชื่อมด้วย bill_id

# ชื่อฟิลด์ Field Name สูตร / ที่มา

สูตร: สถานะสมาชิก (Field 19)

  • IF วันปัจจุบัน > วันหมดอายุ → "Expired"
  • IF วันปัจจุบัน ≤ วันหมดอายุ → "Active"

สูตร: ระดับสมาชิก (Field 21)

คำนวณจากยอดสะสมหลัง Rerank — เมื่อยอดสะสมถึงเกณฑ์ที่กำหนด สมาชิกจะถูกเลื่อนระดับ (เช่น Classic → Platinum)

5. กลุ่ม 3 — อายุสมาชิก & วันหมดอายุ

ข้อมูลที่เกี่ยวกับระยะเวลาการเป็นสมาชิกและวันหมดอายุ

# ชื่อฟิลด์ Field Name สูตร / ที่มา หน่วย
23 อายุสมาชิก (วัน) membership_age_day คำนวณ วัน
24 อายุสมาชิก (เดือน) membership_age_month คำนวณ เดือน
25 วันหมดอายุ membership_expiry_date คำนวณ วันที่
26 ช่องทางสมัคร register_channel Input (POS / Web CRM) —
27 พนักงาน staff_name Input —
28 สาขาที่สมัคร register_branch Input —

สูตรที่ใช้

  • อายุสมาชิก (วัน) = TODAY() - register_date
  • อายุสมาชิก (เดือน) = DATEDIF(register_date, TODAY(), "M")
  • วันหมดอายุ = register_date + จำนวนเดือนจากแพ็กเกจ

6. กลุ่ม 4 — พฤติกรรมการใช้บริการ

ข้อมูลที่คำนวณจากรายงานบิล แสดงพฤติกรรมการใช้บริการของสมาชิก

⚡
เงื่อนไข: ทุก Field ในกลุ่มนี้ใช้เฉพาะบิลที่ bill_status = "สำเร็จ" และรวมทุกสาขา
# ชื่อฟิลด์ Field Name สูตร แหล่งข้อมูล
29 ใช้บริการล่าสุด last_visit_date MAX(Close_Date) ของสมาชิก รายงานบิล
30 กลุ่ม RFM rfm_segment คำนวณแยก (สูตร RFM) คำนวณแยก
31 กลุ่ม Lifecycle lifecycle_segment คำนวณแยก (สูตร Lifecycle) คำนวณแยก
32 ลักษณะลูกค้า customer_type MODE(customer_type) จากบิลทั้งหมด รายงานบิล
33 โปรโมชันที่ใช้ล่าสุด last_promotion_used ค่าล่าสุดจาก discount_name (ที่ไม่ว่าง) รายงานบิล
34 วัน เวลาที่ใช้บริการบ่อย frequent_visit_datetime MODE(วัน + ช่วงเวลา) รายงานบิล
35 ช่องทางใช้บริการบ่อย frequent_service_channel MODE(sales_channel) รายงานบิล
# ชื่อฟิลด์ Field Name สูตร แหล่งข้อมูล
36 หมวดหมู่ทานบ่อย frequent_food_category MODE(item_category) รายละเอียดบิล
37 เมนูทานบ่อย 1 top_menu_1 item_name ที่มี SUM(item_qty) มากสุด อันดับ 1 รายละเอียดบิล
38 เมนูทานบ่อย 2 top_menu_2 item_name ที่มี SUM(item_qty) มากสุด อันดับ 2 รายละเอียดบิล
39 เมนูทานบ่อย 3 top_menu_3 item_name ที่มี SUM(item_qty) มากสุด อันดับ 3 รายละเอียดบิล
40 ระยะห่างการใช้บริการล่าสุด recency_day TODAY() - last_visit_date รายงานบิล
41 สาขาที่ใช้บริการบ่อย frequent_branch MODE(branch_name) รายงานบิล

สูตร: ลักษณะลูกค้า (Field 32)

  • customer_type = MODE(customer_type จากบิลทั้งหมดที่สำเร็จ)
  • ตัวอย่าง: ถ้าบิล 5 ใบ มี customer_type เป็น "ทานที่ร้าน" 3 ใบ, "Delivery" 2 ใบ → ผลลัพธ์ = "ทานที่ร้าน"

สูตร: วัน เวลาที่ใช้บริการบ่อย (Field 34)

  • แปลง Open_Date → ชื่อวัน (จันทร์-อาทิตย์)
  • แปลง Open_Time → ช่วงเวลา: กลางวัน (10:00-14:59), บ่าย (15:00-16:59), เย็น (17:00-18:59), ค่ำ (19:00-22:00)
  • รวมเป็น "วัน + ช่วงเวลา" เช่น "วันอาทิตย์ กลางวัน"
  • หา MODE (ค่าที่ปรากฏมากที่สุด)

สูตร: เมนูทานบ่อย (Field 37-39)

  • GROUP BY item_name จากรายงานรายละเอียดบิลของสมาชิก
  • SUM(item_qty) ของแต่ละ item_name
  • ORDER BY SUM(item_qty) DESC
  • เลือก 3 อันดับแรก → top_menu_1, top_menu_2, top_menu_3

7. กลุ่ม 5 — ยอดซื้อ & ความถี่

ข้อมูลเชิงปริมาณ: จำนวนครั้ง, ยอดเงิน, ค่าเฉลี่ย ที่คำนวณจากรายงานบิล

# ชื่อฟิลด์ Field Name สูตร เงื่อนไข
42 จำนวนการซื้อทั้งหมด total_orders_lifetime COUNT(bills) ของสมาชิก สำเร็จ
43 ยอดใช้จ่ายตลอดอายุ total_spend_lifetime SUM(Total_Net_Sales) สำเร็จ
44 ยอดสะสมหลัง Rerank spend_since_last_rerank SUM(Total_Net_Sales) หลังวัน Rerank ล่าสุด สำเร็จ
45 จำนวนคน TC avg_party_size_tc SUM(customer_count) จากบิลทั้งหมด สำเร็จ
46 เฉลี่ยต่อคน TA avg_spend_per_person_ta total_spend_lifetime / SUM(customer_count) สำเร็จ
47 ยอดเฉลี่ยต่อครั้ง avg_spend_per_visit total_spend_lifetime / total_orders_lifetime สำเร็จ
# ชื่อฟิลด์ Field Name สูตร เงื่อนไข
48 ความถี่ 0-1 เดือน orders_first_1m COUNT(bills WHERE Close_Date ≤ register_date + 30 วัน) สำเร็จ
49 ความถี่ 0-6 เดือน orders_first_6m COUNT(bills WHERE Close_Date ≤ register_date + 180 วัน) สำเร็จ
50 ความถี่ 0-12 เดือน orders_first_1y COUNT(bills WHERE Close_Date ≤ register_date + 365 วัน) สำเร็จ
51 เฉลี่ยจาน/ครั้ง avg_dish_per_visit SUM(item_qty) / total_orders_lifetime สำเร็จ
52 ระยะห่างเฉลี่ยระหว่างการซื้อ avg_visit_interval_day membership_age_day / total_orders_lifetime total_orders ≥ 2
53 เฉลี่ยเวลาทาน/บิล avg_dine_time_min AVG(bill_duration) สำเร็จ + ทานที่ร้าน
54 ใช้บริการเฉลี่ย/เดือน avg_visit_per_month total_orders_lifetime / membership_age_month membership_age_month > 0
55 LTV ต่อปี ltv_annual avg_spend_per_visit × avg_visit_per_month × 12 —
56 ความหลากหลายเมนู menu_diversity_score COUNT(DISTINCT item_name) สำเร็จ

สูตรสำคัญในกลุ่มนี้

📊
ยอดเฉลี่ยต่อครั้ง (Field 47)
Average Spend per Visit
  • avg_spend_per_visit = total_spend_lifetime / total_orders_lifetime
  • ตัวอย่าง: ยอดรวม 50,000 บาท / มา 20 ครั้ง = เฉลี่ย 2,500 บาท/ครั้ง
📅
ระยะห่างเฉลี่ยระหว่างการซื้อ (Field 52)
Average Visit Interval
  • avg_visit_interval_day = (TODAY() - register_date) / total_orders_lifetime
  • ตัวอย่าง: เป็นสมาชิก 180 วัน / มา 6 ครั้ง = เฉลี่ย 30 วัน/ครั้ง
  • หมายเหตุ: ใช้ได้เมื่อ total_orders ≥ 2
💰
LTV ต่อปี (Field 55)
Lifetime Value Annual
  • ltv_annual = avg_spend_per_visit × avg_visit_per_month × 12
  • ตัวอย่าง: 2,500 บาท/ครั้ง × 2 ครั้ง/เดือน × 12 = 60,000 บาท/ปี

8. กลุ่ม 6 — คะแนน (Points)

ระบบคะแนนสะสมของสมาชิก คำนวณจากเหตุการณ์คะแนนต่างๆ

# ชื่อฟิลด์ Field Name สูตร
57 โปรโมชันล่าสุด last_promotion ชื่อโปรโมชันที่ใช้ล่าสุด
58 คะแนนที่ได้รับทั้งหมด total_points_earned SUM(Earned) + SUM(Migrate) + SUM(Adjusted Increase) + SUM(Refund)
59 คะแนนหลัง Rerank points_earned_since_rerank SUM(points +) หลังวัน Rerank ล่าสุด
60 คะแนนที่ใช้ทั้งหมด total_points_redeemed SUM(Used)
61 คะแนนที่หมดอายุ total_points_expired SUM(Expired)
62 คะแนนคงเหลือ points_balance earned - redeemed - expired - deducted

สูตรคะแนนคงเหลือ (Field 62)

  • total_points_earned = SUM(Earned) + SUM(Migrate) + SUM(Adjusted Increase) + SUM(Refund)
  • total_points_redeemed = SUM(Used)
  • total_points_expired = SUM(Expired)
  • total_points_deducted = SUM(Returned) + SUM(Adjusted Decrease)
  • points_balance = total_points_earned - total_points_redeemed - total_points_expired - total_points_deducted

อัตราคะแนนต่อบิล

⭐
อัตราคะแนน: ทุก 5 บาท = 1 คะแนน (Net Sales ÷ 5) หรือ Net Sales × 20%
  • points_earned_per_bill = ROUND(Total_Net_Sales ÷ 5)
  • ตัวอย่าง: บิล ฿1,215 → 1,215 ÷ 5 = 243 คะแนน
  • ตัวอย่าง: บิล ฿3,674 → 3,674 ÷ 5 = 734.8 ≈ 735 คะแนน
  • ตัวอย่าง: บิล ฿424 → 424 ÷ 5 = 84.8 ≈ 85 คะแนน
  • ตัวอย่าง: บิล ฿3,500 → 3,500 ÷ 5 = 700 คะแนน

9. กลุ่ม 7 — เครดิต (Credits)

ระบบเครดิตสะสมของสมาชิก คล้ายระบบคะแนนแต่แยกต่างหาก

# ชื่อฟิลด์ Field Name สูตร
63 เครดิตที่ได้รับทั้งหมด total_credits_earned รวมเครดิตที่ได้รับจากทุกแหล่ง
64 เครดิตที่ใช้ทั้งหมด total_credits_redeemed รวมเครดิตที่ใช้
65 เครดิตที่หมดอายุ total_credits_expired เครดิตที่เกินอายุ
66 เครดิตคงเหลือ credits_balance earned - redeemed - expired

สูตรเครดิตคงเหลือ (Field 66)

  • credits_balance = total_credits_earned - total_credits_redeemed - total_credits_expired

10. ตารางเหตุการณ์คะแนน

ระบบบันทึกประวัติคะแนนเป็น "เหตุการณ์" แต่ละรายการ แบ่งเป็น 2 กลุ่ม:

เหตุการณ์ที่ทำให้คะแนนเพิ่ม (+)

ประเภท ชื่อเหตุการณ์ คำอธิบาย ที่มา
Earned สมัครสมาชิกแรกเข้า คะแนนที่ได้ตอนสมัครสมาชิก ตั้งค่าจากระบบ
Earned ได้รับคะแนนบิล คะแนนจากยอดซื้อ (Net Sales ÷ 5) รายงานบิล (สำเร็จ)
Migrate นำเข้าข้อมูล คะแนนที่ Import ผ่านชีท (ย้ายระบบ) Admin import
Adjusted + แก้ไขคะแนนเพิ่ม Admin ปรับคะแนนเพิ่มให้ลูกค้า Admin manual
Refund ยกเลิกคะแนนที่ใช้ ยกเลิกบิล → คะแนนที่เคยใช้ได้คืน ยกเลิกบิล

เหตุการณ์ที่ทำให้คะแนนลด (-)

ประเภท ชื่อเหตุการณ์ คำอธิบาย ที่มา
Used ตัดใช้คะแนน ลูกค้าใช้คะแนนแลกส่วนลด/ของรางวัล รายงานบิล (สำเร็จ)
Returned ยกเลิกคะแนนที่ได้รับ ยกเลิกบิล → คืนคะแนนที่เคยได้รับ ยกเลิกบิล
Adjusted - แก้ไขคะแนนลด Admin ปรับคะแนนลดให้ลูกค้า Admin manual
Expired คะแนนหมดอายุ คะแนนเกินอายุตามนโยบาย ระบบอัตโนมัติ

ตัวอย่างการคำนวณคะแนน

11. แผนผังความสัมพันธ์ข้อมูล

แผนผังแสดงว่าข้อมูลจากแต่ละแหล่งถูกนำไปคำนวณ Field ใดบ้าง

รายงานบิล (bills) — 1 แถว = 1 บิล ├── bill_status = "สำเร็จ" AND ไม่ใช่ "ไม่คิดรายได้" (filter) ├── → last_visit_date (MAX Close_Date) ├── → recency_day (TODAY - last_visit) ├── → total_orders_lifetime (COUNT bills) ├── → total_spend_lifetime (SUM Net_Sales) ├── → avg_spend_per_visit (spend / orders) ├── → avg_party_size_tc (SUM customer_count) ├── → avg_spend_per_person_ta (spend / SUM customer_count) ├── → orders_first_1m/6m/1y (COUNT by date range) ├── → avg_dine_time_min (AVG bill_duration) ├── → customer_type (MODE) ├── → frequent_visit_datetime (MODE วัน+เวลา) ├── → frequent_service_channel (MODE sales_channel) ├── → frequent_branch (MODE branch_name) ├── → total_points_earned (SUM points_earned) └── → total_points_redeemed (SUM points_used)
รายงานรายละเอียดบิล (bill_items) — 1 แถว = 1 รายการเมนูในบิล ├── bill_status = "สำเร็จ" AND ไม่ใช่ "ไม่คิดรายได้" (filter ผ่าน bill_id) ├── → top_menu_1/2/3 (TOP 3 item_name by SUM item_qty) ├── → frequent_food_category (MODE item_category) ├── → avg_dish_per_visit (SUM item_qty / total_orders) └── → menu_diversity_score (COUNT DISTINCT item_name)
ข้อมูลสมาชิก (member) ├── register_date │ ├── → membership_age_day (TODAY - register_date) │ ├── → membership_age_month (DATEDIF) │ └── → membership_expiry_date (register_date + package_months) ├── membership_expiry_date │ └── → member_status (Active/Expired) └── total_spend / recency / frequency ├── → rfm_segment (RFM scoring) └── → lifecycle_segment (Lifecycle rules)
